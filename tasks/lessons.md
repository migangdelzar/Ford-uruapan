# Implementation lessons

- Failure mode: the protected Terraform Vault plan guard constrained resource addresses and change actions but accepted arbitrary in-place policy statement changes, including a synthetic `manage all-resources in tenancy` grant. Detection: a new regression case passed against the old guard when it should have been rejected. Prevention: have Terraform and the guard consume the same exact identity/secret contract; validate every planned statement against expected Vault and compartment OCIDs in both plan and apply jobs.
- Failure mode: an OCID validator allowed only alphanumerics and periods, rejecting valid OCI-shaped identifiers containing underscores. Detection: a regression case using an underscore-bearing vault/compartment identifier failed validation. Prevention: accept the OCI identifier character set and keep an underscore/hyphen case in the plan-guard tests.
- Failure mode: a policy guard checked exact grant statements but ignored changes to the IAM policy's metadata or attachment compartment. Detection: a renamed policy with otherwise valid statements passed the guard. Prevention: compare all before/after policy fields except the intended `statements` field and reject unknown values.

- Failure mode: an exact-trim comparison URL was added to the versioned view and row mapper but omitted from the trim lookup SELECT list. Detection: focused H2 lookups failed with a missing-column SQL error before exercising the mapper. Prevention: verify each view-backed output field in the migration, production query projection, row mapper, and restored-snapshot assertion together; fixture availability alone is insufficient.

- Spring proxies require transactional adapter classes to remain subclassable; do not mark a proxied repository `final`.
- Keep tests aligned with record accessor names when extending immutable decision objects (`handoffRecommendation()` rather than a shortened alias).
- Spring Modulith module boundaries include configuration method signatures; cross-module diagnostics should consume primitive properties rather than non-exposed configuration types.
- Separate-service placement must follow the user's explicit topology: local MCP + its own Cloudflare ingress, with only the client URL configured remotely; do not move a workload to an Emme VM because adjacent services run there.
- The repository ignores directories named `out/` globally, which hides new Java adapter sources and tests under `adapter/out/`; check `git check-ignore` for new paths and place new files where they remain visible.
- Live provider tests depend on external model/config state; disable Gradle up-to-date reuse or a “passing” preflight may be a stale result.
- Short affirmations must be interpreted against the immediately pending offer/question. Classifying only the literal reply (for example, “sí me gustaría”) can fall back to GENERAL and restart discovery; persist the next workflow slot deterministically and do not depend on generated prose to advance state.
- Spring Security OAuth2 Resource Server validates access tokens; it does not issue them. Before designing login, inspect `SecurityConfiguration` and use the same external OIDC issuer, rather than describing Spring as the issuer.
- Spring Modulith observability creates CGLIB proxies for observed beans; keep observed Spring components subclassable. `final` classes can prevent the app context from starting.
- A shared deployment action may execute Ansible roles from the caller repository; when duplicated templates exist, verify the effective runtime config and edit its source, then confirm behavior through a production request.
- Failure mode: host-side Testcontainers could not reach Ryuk at Colima's forwarded localhost port, before the PostgreSQL test started. Detection: initialization error `Could not connect to Ryuk at localhost:<port>`. Prevention: run the Docker-backed test from the existing host-network test runner, copy source to a unique temporary workspace, leave its existing workspace intact, and remove only the workspace created for that run.
- Failure mode: creating a temporary runner with `docker create` did not start its process, so `docker exec` failed with “container is not running.” Detection: container exists but is stopped immediately after create. Prevention: explicitly `docker start` a created container, or use `docker run`; always clean up the exact temporary container ID in a `finally` block.
- Failure mode: a fixture named `Dato sin fecha` pointed to a page with a valid crawl timestamp, so the complete-evidence view correctly retained it and contradicted the assertion. Detection: the page row itself supplied `crawled_at`, despite the fixture's label. Prevention: model missing evidence in the referenced source row (here, a source URL with null crawl time), and assert against the data rather than fixture names.
- Failure mode: archiving a Gradle project with a broad `--exclude='./out'` omitted source packages named `adapter/out`, producing hundreds of misleading Java missing-symbol errors. Detection: the extracted source tree lacked application ports and output adapters. Prevention: exclude only known build outputs, preserve package directories named `out`, and use `tar --no-xattrs --no-mac-metadata` to suppress macOS archive metadata.

- Failure mode: registering a new `final` policy class as a `@Bean` broke app-context startup with `Cannot subclass final class ...` because the service's AOP/Modulith layer CGLIB-proxies beans. Detection: `FordServiceApplicationTest`/`LiquibaseStartupTest` failed with `AopConfigException` → `IllegalArgumentException`. Prevention: keep any class exposed as a Spring bean subclassable; only `final` is safe for plain value/helper classes that are never registered as beans.
- Failure mode: parallel worktrees that each add a Liquibase change independently all picked `025` and edited `db.changelog-master.yaml`, guaranteeing a merge collision. Detection: three branches (`handoff`, `whatsapp`, `shadow`) each contain `changes/025-*.yaml`. Prevention: assign each worktree a distinct migration number up front, or renumber and re-assert ordering when integrating branches.
- Failure mode: adding a second constructor to an existing Spring bean (a new shadow-mode dependency) with neither constructor annotated made Spring unable to choose one; every DB integration test failed with `BeanInstantiationException: No default constructor found` → `Failed to load ApplicationContext`. Detection: a single root `IllegalStateException` failing *all* context tests at once is a wiring/context problem, not a per-test bug. Prevention: when a bean gains constructor overloads, annotate the injectable one with `@Autowired` (repo convention), keep the old signature delegating for tests.
- Failure mode: an integration test class sharing one static Testcontainers database failed only when the whole class ran, looking like a duplicate/race bug (`["wamid.1","wamid.1",...]`). A global `claimDue` query in a later test consumed rows left unclaimed by earlier tests. Detection: the failing method passed in isolation but failed in the full class; a debug print showed extra DB rows, not mapper duplication. Prevention: truncate state in `@BeforeEach` (or scope each test's data) for shared static containers.
- Failure mode: a Postgres exactly-once claim must be a single atomic statement; a read-then-delete/claim can double-claim under concurrency. Prevention: use `WITH due AS (SELECT ... FOR UPDATE SKIP LOCKED) DELETE ... USING due RETURNING ...` (or `UPDATE ... SET claimed_at=now() WHERE claimed_at IS NULL RETURNING ...`).
- Failure mode: changing deterministic customer-facing copy (dropping an advisor response-time promise) updated the unit test but not the integration-test assertion, so `integrationTest` failed while `test` was green. Prevention: when service copy changes, grep integration tests for the old string too; unit green does not imply integration green.
- Failure mode: verifying a "local Compose" stack from a git worktree under `/private/tmp` fails even though the build succeeds — Colima does not share `/private/tmp` into its VM, so host file bind-mounts (e.g. `otel-collector` `tempo-config.yaml`) error with `not a directory: Are you trying to mount a directory onto a file`. Detection: `docker compose up` builds images fine, then one service fails `OCI runtime create failed ... not a directory`. Prevention: place the worktree under `$HOME` when you need Colima bind-mounts, or verify the app+health path directly with `docker run` (mirrors the CI native smoke).
- Failure mode: assuming the local deploy secret gate matches production runtime. `require_deploy_config` (`.mise/lib/remote.sh:109`) demands plaintext secrets on the workstation, while the prod app loads them from OCI Vault (`FORD_VAULT_SECRET_OCID_*` in `app.env.j2`). Detection: `deploy:check` reports plaintext secrets missing even though the deployed stack is healthy. Prevention: materialize the workstation copy from the authoritative source — `oci secrets secret-bundle get --secret-id <ocid> --query 'data."secret-bundle-content".content' --raw-output | base64 --decode` (note the kebab-case field name; `oci vault secret` has no `get-secret-version`). Write with the repo's own `set_deploy_secret` so values stay single-line, mode 600, gitignored.
- Failure mode: the OCI CLI silently picks up an invalid profile from `deployment/config/oci.env` (`OCI_CLI_CONFIG_FILE` → `ford-vault-bootstrap.config` stub) and fails with `user missing`. Detection: `oci os ns get` errors on config validation. Prevention: `env -u OCI_CLI_CONFIG_FILE OCI_CLI_PROFILE=migueldelzar oci ...` (the session-token profile in `~/.oci/config`).

- Avoid product-specific names in domain classes, runtime properties, and generic evaluation infrastructure. Before adding a guard or policy for a feature, search for an existing shared policy and extend/reuse it; duplicate safety rules drift. Keep any required product label in customer-facing copy or documentation only.
- Failure mode: a synthetic policy-evaluation timer was labeled as first-response latency, which could falsely imply provider-to-customer latency had been measured. Detection: report description did not match the timed code path. Prevention: name each metric for the exact boundary measured, and explicitly label synthetic/local measurements; never substitute policy runtime for end-to-end latency.
- User correction: do not imply a broad migration is complete when only local source has changed. State the exact production blockers and the next safe actions up front; distinguish deleted deploy code from still-running remote containers, tunnels, secrets, and permissions. Never claim release/deployment or external cleanup without direct evidence.
- Failure mode: grounding numeric claims with substring matching let an unsupported short number pass when it appeared inside a larger supported value (for example, claim `500` inside evidence `650000`), while single-digit claims were skipped entirely. Prevention: compare normalized complete numeric tokens and include every numeric claim in the deterministic check; add regressions for partial and single-digit claims.
- Failure mode: revoking an old runtime's Vault grant before stopping its process can break restart and rollback; the replacement scraper scheduler still resolves the shared PostgreSQL password from Vault. Prevention: trace runtime secret consumers through startup and rollback before policy cleanup; retire old consumers first and preserve grants required by the replacement scheduler.
